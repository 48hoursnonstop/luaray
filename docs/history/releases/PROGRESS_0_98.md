# LuaRay 0.98.0-dev — indexed and selected ndarray writes

## Provenance

Continues the supplied, integrity-verified 0.97 archive, SHA-256
`09e6d61e43a5806d3daa7fa0ff328db9dd4b2331d005665f6f33f62c490c0f3b`.
The baseline passed all 603 file hashes and all 112 historical differential
fixture files before implementation. Its reconstruction from 0.94 and the
unverified equivalence to unavailable 0.95/0.96 archives remain explicit.

## Implementation

- Native C `ln_write` subsystem with Lua `np.put` / `a:put` and `np.place`.
- Logical C-order flattening, cyclic values, repeated indices, negative indices,
  raise/wrap/clip modes and in-place writes to actual shared storage.
- Source-derived alias semantics: put protects overlapping operands with
  destination-copy/writeback; place reads compatible contiguous aliased values
  live. Noncontiguous writeback and error discard are tested.
- Native dtype conversion distinguishes strong ndarrays from directly packed
  Lua scalars/tables. Place enforces safe array casts, put permits unsafe array
  casts, mask coercion covers numeric/complex/string values.
- Fix existing empty/whitespace-string numeric conversion and empty-string
  timedelta-to-NaT behavior in the shared conversion subsystem.
- Discover installed CBLAS using pkg-config, including Arch's separate libcblas.
  No dependency installation, system configuration or Python runtime required.

## Executed evidence

- `make full-test`: all **114 differential fixture files** passed, including the
  112 historical fixtures and new put/place suites; C/Lua regressions passed.
- **1,002 put cases + 733 place cases = 1,735 original executable-oracle cases**,
  **42,754 comparisons**, generated by **NumPy 2.5.3**. Historical frozen suites
  retain their stated older oracle provenance. Metadata-only release assertions
  in existing tests now require 0.98; numerical expectations were not changed.
- **94 targeted Lua regression checks** and the native C write test passed.
  The actual public `require('luaray')` example executed through Lua 5.4 and the
  built shared module.
- The three modified C translation units (`ln_write`, `ln_dtype_transfer`,
  `lua_module`) passed directed ASan/UBSan native/Lua testing, including both
  new fixtures and the 0.97 memory suites. Other dependencies were uninstrumented;
  leak detection was disabled.
- Frozen fixture regeneration was checked byte-for-byte; the final blocked
  provenance extension is checked again by the release preparation command.
- `make release` produces the source-only archive, manifest and SHA-256, extracts
  it, recompiles, reruns full-test and executes the example. Actual final results
  are recorded in its verification JSON and clean-build log; an archive without
  a successful report is not a verified release.

## Explicit boundaries

- Lua positive indices start at 1, negatives follow the end, and zero is invalid
  in every mode. Clip-mode negatives select the first element, as upstream.
- **40 additional original states remain blocked by unavailable non-native
  numeric byte-order descriptors**. Their complete initial/expected states and
  operands are retained in `tests/write98_blocked_reference.lua`; an executed
  diagnostic asserts the constructor limitation. They are not parity passes.
- No object/structured dtype, Python subclass, exception-class or comprehensive
  warning compatibility is claimed. The pre-existing 0.97 exact-memory work
  limits and other recorded subsystem limitations remain.
- English and Spanish contracts are in `docs/en/writing.md` and
  `docs/es/writing.md`. This version does not establish full NumPy parity.
